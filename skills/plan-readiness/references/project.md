# Project or product planning

Create the master `plan.md` and only the child plans needed to establish execution-ready work.

## Derive

- system/capability inventory from the approved project specification;
- foundation enablers and the downstream work each unlocks;
- functionality/epic map and independently demonstrable features;
- dependency graph, critical path, phases, entry/exit gates, and integration points;
- parallel workstreams, contracts, worktrees, branches, environments, engineers, agents, supervision load, review/integration capacity, and ready queues;
- test/eval infrastructure, security and tenant-isolation gates, migration, rollout, rollback, operations, and documentation.

## Ask only after inspection

- Which engineers are available, with what domain authority and supervision capacity?
- Which local, cloud, and sandbox runtimes are available to coding agents?
- What branch protection, review, integration, and production gates already exist?
- Which foundations must be built versus reused?
- Which deliverable slice should become the first end-to-end proof?

## Required result

Produce a master orchestration plan. Create enabler, epic, feature, and task plans progressively; do not prematurely detail every distant task against an unstable repository. Mark later phases planned at lower confidence and define their refinement gate.

Do not treat dates as the primary structure. Build dependencies and capacity first, then derive a delivery range when requested.
